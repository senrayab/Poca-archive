# POCA — 포토카드 아카이브

소장 중인 포토카드를 썸네일로 모아보는 **로컬 우선(local-first) PWA**입니다.
사진은 서버로 올라가지 않고 브라우저(IndexedDB) 안에만 저장되며, 업로드 시 자동으로 WebP로 변환해 용량을 줄입니다.

## 배포된 주소

<https://senrayab.github.io/Poca-archive/>

`main`에 push하면 GitHub Actions가 빌드해서 자동으로 올립니다(`.github/workflows/deploy.yml`).
폰에서 이 주소를 열고 **홈 화면에 추가**하면 오프라인에서도 열립니다.

> 데이터는 기기별 브라우저 안에만 있습니다. PC에서 등록한 카드는 폰에 자동으로 오지 않으니,
> 옮기려면 설정 → **백업 내보내기**로 ZIP을 받아 폰에서 **백업 가져오기** 하세요.

## 실행

```bash
npm install
npm run dev      # http://localhost:5173 (같은 와이파이의 폰에서도 접속 가능)
npm run build    # dist/ 정적 파일 생성
npm run preview  # 빌드 결과 확인
```

폰에서 열어 **홈 화면에 추가**하면 주소창 없이 앱처럼 뜨고 오프라인에서도 보관함을 볼 수 있습니다.

## 화면 구성

| 경로 | 화면 | 설명 |
| --- | --- | --- |
| `/` | 보관함 | 멤버 탭 + 카테고리 필터 + 썸네일 그리드 |
| `/favorites` | 즐겨찾기 | 하트를 누른 카드만 |
| `/trash` | 휴지통 | 양도·판매로 정리한 카드 (되돌리기 / 완전 삭제) |
| `/upload` | 등록 | 멤버·카테고리 선택 후 다중 업로드, WebP 변환 |
| `/members` | 멤버·카테고리 관리 | 이름·색·순서 편집, 추가/삭제 |
| `/stats` | 통계 | 멤버별·카테고리별 장수, 양도/판매 기록, 저장 용량 |
| `/settings` | 백업·설정 | ZIP 내보내기/가져오기, 저장소 상태, 초기화 |

## 요청한 기능이 어디에 있는지

- **멤버 탭 + `+` 로 사람 추가** — `src/components/MemberTabs.tsx`. 상단 칩 맨 끝의 `+`, 또는 서랍 → 멤버 관리.
- **서랍(드로어) 메뉴** — `src/components/Drawer.tsx`. 헤더 왼쪽 햄버거.
- **썸네일 클릭 → 레이어 팝업** — `src/components/CardDetail.tsx`. 이미지 아래에 등록 당시 제목·멤버·카테고리·메모가 붙고, 좌우 화살표/스와이프/키보드로 다음 카드로 넘어갑니다.
- **휴지통 버튼** — 상세 팝업의 삭제 버튼. 바로 지우지 않고 **양도함 / 판매함 / 그냥 삭제** 중 사유를 고른 뒤 휴지통으로 옮깁니다. 사유는 통계에 남습니다.
- **업로드 플로팅 메뉴** — `src/components/Fab.tsx`. 오른쪽 아래 `+`를 누르면 *사진 골라서 등록 / 등록 화면 열기 / 멤버 추가* 가 펼쳐집니다.
- **업로드 화면 + WebP 변환** — `src/pages/UploadPage.tsx`, 변환 로직은 `src/lib/image.ts`.
  긴 변 1600px(본체) / 420px(썸네일)로 리사이즈 후 WebP 인코딩하며, 원본 대비 절감률을 화면에 보여줍니다.
  WebP 인코딩을 지원하지 않는 브라우저에서는 자동으로 JPEG로 떨어집니다.

## 추가로 넣은 것

- **다중 선택** — 썸네일을 우클릭(모바일에서는 길게 누르기)하면 선택 모드. 여러 장을 한 번에 휴지통으로 보내거나 되돌립니다.
- **검색** — 제목·메모 대상. 헤더 돋보기 버튼.
- **즐겨찾기** — 상세 팝업의 하트.
- **ZIP 백업 / 복원** — `src/lib/backup.ts`. 이미지 원본과 `manifest.json`을 한 파일로 묶습니다.
  가져오기는 같은 id를 건너뛰므로 여러 기기의 백업을 이어붙여도 중복이 생기지 않습니다.
- **영구 저장 요청** — 설정 화면에서 `navigator.storage.persist()`를 호출해 브라우저가 데이터를 임의로 비우지 않게 합니다.
- **다크 / 라이트 테마** — 설정 → 인터페이스. `시스템 / 라이트 / 다크` 중 선택하며, 시스템은 OS 다크 모드를 실시간으로 따라갑니다.
  선택값은 `localStorage`에 남고, `index.html`의 인라인 스크립트가 첫 페인트 전에 적용해 전환 시 화면이 번쩍이지 않습니다.

## 데이터 모델 (`src/db/types.ts`)

```
Member      { id, name, color, order }
Category    { id, name, order }
Card        { id, title, memberId, categoryId, memo,
              thumb(WebP Blob), width, height, bytes,
              favorite 0|1, deleted 0|1, deletedAt, status: own|traded|sold }
StoredImage { cardId, blob }   ← 1600px 본체. 상세 팝업을 열 때만 읽는다
```

- **본체 이미지를 별도 테이블(`images`)로 분리**했습니다. 썸네일 그리드는 `cards`만 조회하므로
  카드가 수백 장이어도 원본이 메모리에 올라오지 않습니다. (schema v2, 기존 데이터는 자동 마이그레이션)
- 상세 팝업은 원본이 디코드될 때까지 썸네일을 흐리게 깔아 빈 화면을 보이지 않습니다.
- `deleted`/`favorite`가 boolean이 아니라 `0|1`인 이유는 IndexedDB가 boolean을 인덱싱하지 못하기 때문입니다.
- 삭제는 항상 소프트 삭제(`deleted = 1`)이고, 완전 삭제는 휴지통에서만 일어납니다.
  완전 삭제는 반드시 `purgeCards()`를 거쳐야 `images` 행까지 같이 지워집니다.

## 주의

데이터가 브라우저 안에만 있으므로 **브라우저 데이터를 지우거나 기기를 바꾸면 사라집니다.**
설정 → 백업 내보내기로 주기적으로 ZIP을 받아 클라우드 드라이브에 올려두세요.
